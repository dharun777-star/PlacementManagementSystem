Architecture & Project Highlights

For Viva & Examiner

Stack: HTML5, Modern CSS3, Vanilla JS (ES6+), Python Django 6, Django REST Framework, SQLite Database.

Key Relational Architecture:

  • Student Model: Roll ID (Unique), Name, Email (Unique), Phone, Department, Year, CGPA (0-10), Skills, Placement Status.
  • Company Model: Company ID (Unique), Company Name, HR Name, HR Email, Role, Package (LPA > 0), Location, Drive Date.
  • Placement Model: Links Student (FK) and Company (FK) with role, package, placement date, and status. Automatic synchronization of Student's placement status on create, update, or delete!

Frequently Asked Viva Questions

Preparation
Q1: Why did you use Django REST Framework (DRF)?

DRF provides clean serialization, declarative model serializers, automatic validation, viewsets, and standard HTTP response codes for decoupled frontend-backend communication.

Q2: How does the system prevent duplicate students or companies?

At the database level via unique=True constraints on student_id, email, and company_id, backed by custom serializer validators that catch duplicates before saving.

Q3: How is student placement status kept consistent?

The Placement model overrides save() and delete(): when an offer is assigned, the student's status immediately switches to "Placed". If all active placements are removed, it safely reverts to "Not Placed".
